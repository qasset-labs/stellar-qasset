# Community conduct and support

Project discussions should be respectful, specific and evidence-based. Welcome
questions and corrections. Critique technical decisions without personal attacks.
Harassment, threats, discrimination, doxxing, deliberate disclosure of private
keys/customer data, and sustained disruption are unacceptable. Respect private
security coordination and do not pressure contributors to disclose secrets.

This policy covers project issues, pull requests and other project-operated
community channels. Repository moderators with actual permissions may request
corrections, remove harmful content or restrict participation proportionately.
Record reasons where doing so does not reveal private information. No moderator
or private conduct-report address is appointed here; governance must establish
an accessible reporting/escalation route before operating additional channels.
Use available repository moderation/reporting controls for immediate concerns.
Do not publish sensitive conduct details merely to create a public report.

Public support belongs in the
[issue tracker](https://github.com/qasset-labs/stellar-qasset/issues), with versions,
supported configuration, expected/actual behavior and public-fixture reproduction.
There is no promised support SLA, emergency custody service or ability to reverse
ledger transactions, restore lost keys or undo issuer locks. Vulnerabilities
follow [security reporting](SECURITY.md); routine issues should not contain
private keys, mnemonic phrases, confidential records or pending credentials.

Constructive participation does not grant repository administration, release
rights or ownership. Appointments and escalation responsibility remain subject to
[governance](GOVERNANCE.md).
