# Experimental Binius64 verifier port

This isolated research package ports the actual verifier graph from upstream Binius64 revision `115108d5a661d95c0b474b6ab02558bfe6c6bec7` to `no_std + alloc` on `wasm32v1-none`. It verifies the existing 539,888-byte public RFC8032 leaf-seed proof, with the existing 96-bit upstream parameter setting and 232 FRI queries. No parameter is reduced. The upstream code is attributed under its original MIT/Apache licenses. This is not an approved quantum backend, a deployed contract, or production recovery.

The guest executes actual `ZKVerifier::verify` and requires transcript `finalize`. Public words are derived from the same scalar placed in the transcript. The raw Wasm executable additionally requires the exact fixture scalar, whose point equals the independently checked public RFC8032 key. That narrow fixture guard is not generic point validation. The generic library requires its caller to perform the independent scalar-to-protected-key check.

The fixed preprocessing artifact is 2,714,051 bytes, SHA256 `4d6fd19ea0092a261ed7041985b679ecad4b45f9cc6452a7a717979be7c35ef3`. The loader checks this compiled identity before decoding and preserves the exact RS bases, FRI layout, 232 queries, inner circuit and outer padded constraints. The artifact is generated by independently inspected host setup; it is never accepted as a prover-selected verification key. All actual 131,072 padded constraints also match independent native fingerprint `0d289309fc17e9b8e6e2d6a4b99d2cf4350547864fde5f79d7eb06929ee31938`.

## Port findings and scope

- Upstream hashes `usize::to_le_bytes()` for a sampler index during a Fiat-Shamir sampling-to-observation transition. Native64 and Wasm32 therefore hash different byte lengths. The port explicitly uses `u64LE`, preserving the original 64-bit native transcript and original proof. Original native golden transition vector `[394127921, 1463445479, 3541783]` is checked on native and Wasm. A first draft also contained an escaped-text domain typo; actual positive-proof comparison detected it and the domain now exactly matches the original NUL-terminated byte domain. A subsequent valid-proof rejection was independently traced to the upstream index-width issue, rather than assumed to be a valid negative test.
- Three host setup methods and their floating-point query-count calculation are excluded on the guest. Verification has no substituted checks, cryptographic stubs, relaxed parameters or trusted prover-supplied preprocessing.
- Core/allocation imports and dependency defaults are separated from OS services. Transcript file dumping and environment flags are host diagnostics only. No-OS backtraces are diagnostic markers. The unused symbolic frontend uses hashbrown in its allocation mode. Portable arithmetic and the upstream synchronous fallback remain intact.
- Preallocation replaces repeated growth for the exact same constraints. Operand decoding uses inline SmallVec directly. These change allocation behavior without changing constraint order, values, padding, blinding rules, bases or transcript bytes. The immutable artifact and complete padded-constraint hash remain identical.
- An initial 40 MiB bounded bump experiment trapped during artifact loading; this is retained as a failed allocation baseline, not proof that the relation cannot fit. The final fixture uses an import-free, single-threaded, bounded bump allocator and a 40 MiB maximum linear memory. This allocator is experimental, is not a production allocator audit, and is exercised in a fresh instance for each case. Error reporting returns fixed small static strings.

The executable embeds setup and public proof for reproducible execution. Its measured size is much larger than the recorded Soroban contract code cap. Embedding those artifacts is not a proposed contract deployment design. Node/V8 execution timing and static Wasm operator counts are not Soroban instruction metering. Contract ABI, ledger artifact representation, actual Soroban host costs, arbitrary hostile-proof resource bounds, current entitlement/retirement, a generic exact point anchor and independent quantum-knowledge/ZK review remain open.

## Reproduce

Rust 1.94.1 with `wasm32v1-none`, Cargo's cached locked dependencies, Python 3 and Node 22 are required. Supply the retained public canonical setup and proof artifacts; the script rejects other hashes. Generated files stay under `target`.

```sh
python3 scripts/run.py --setup /path/to/fixed-setup.bin --proof /path/to/proof.bin
```

`guest`, `wasm-fixture`, `host-runner` and `inspect` are isolated Cargo packages. The vendored workspace contains only the eleven verifier dependency crates. `evidence` records measured results; `provenance.json` binds source hashes and exact upstream origins. The generated setup, proof, Wasm and executable binaries belong in ignored target directories. No account key, real user seed, RPC call, Stellar transaction or deployment is used.
