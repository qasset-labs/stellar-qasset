# Deterministic Binius64 verifier preprocessing split — local research

This isolated prototype uses Binius64 commit `115108d5a661d95c0b474b6ab02558bfe6c6bec7` and the same fixed SHA-512 leaf-seed/clamp circuit, transcript domain, SHA-256 challenger/Merkle scheme, 96 configured security bits and inverse-rate exponent 1 as the existing Q-Asset public-fixture experiment. It does not change the cryptographic verification protocol or establish quantum security.

`export` executes the frontend and symbolic `ZKVerifier::setup` on the host, then exports operator-trusted preprocessing. It runs the setup/export twice and requires equal bytes. Loading and reexporting must also produce identical bytes; this covers all serialized inner/outer constraints, constants, indices, oracle specifications, FRI rate/batch/query/fold parameters, and exact ordered Reed-Solomon subspace bases. The latter are exported explicitly instead of guessing a default field basis.

`verify` and `selfcheck` load an artifact embedded into the executable with `include_bytes!`; its SHA-256 whitelist is also compiled into the executable. The loader checks its byte bound and exact SHA-256 before ANY nested native decode. It then checks identity, bounds, canonical operand ordering, index ranges, public dimensions, fixed query count/rate/batch, oracle correspondence and exact end of input. Native inner constraints are validated and prepared again. The fixed artifact is public preprocessing, not a trusted answer or stored `valid` result. There is no prover-selected key or expected-hash CLI argument.

At verification time the prototype invokes no circuit builder or symbolic setup. Outer integer padding and `FRIParams::new` reconstruct exact parts directly; no floating-point security estimate or arity optimization runs. The actual `ZKVerifier::verify`, its wrapped outer verifier, compiler-channel completion, and transcript finalization remain in the acceptance path. Public words come from the pinned constraint-system constants and the same scalar observed in the transcript; the original fixture check enforces clamp bits and the independently pinned RFC8032 point.

The binary snapshot contains a format/version domain, upstream Git pin, program domain, SHA-256 of `src/native.rs` containing the exact fixed circuit and public-input binding, fixed security/rate identifiers, the upstream versioned prepared inner-CS encoding, outer unpadded-CS dimensions/constants/operands and blinding parameters, and the complete oracle/FRI configurations. Integers in the local envelope are little-endian u32; field elements and inner-CS use the exact pinned upstream serialization. It is a research-local format, not a standardized or audited verifier-key format.

Three small upstream API additions only provide trusted construction/access: `ZKVerifier::from_preprocessed`, `BaseFoldZKVerifierCompiler::from_preprocessed`, and `ConstraintSystemPadded::unpadded_constraint_system`. They must never be exposed to untrusted selected parameters. The verification loader exposes no expected-hash argument; the immutable hash is compiled internally. The host-only export roundtrip first reserializes the supplied trusted native verifier and requires exact equality, then uses a computed hash solely for that freshly constructed object's roundtrip check.

The prototype is native. It does not establish Soroban compatibility, acceptable instruction/memory cost, deployability, account retirement, or a safe recovery transaction lifecycle. The separate no_std port and transaction-staging experiments require independent integration and testing. Public scalar exposure still requires retiring all classical authorities before publication.

## Measured evidence

`result.json` records the final source and executable hashes. The fixed artifact is 2,714,051 bytes (SHA-256 `4d6fd19ea0092a261ed7041985b679ecad4b45f9cc6452a7a717979be7c35ef3`). Repeated exports and loaded reexports match byte-for-byte. The actual 539,888-byte retained proof verifies, with 12 functional/boundary checks passing; strict Clippy and formatting checks pass. One final native measurement is 0.0635 seconds load and 0.1503 seconds proof verification, with 42,732 KiB maximum RSS. These are local samples, not controlled performance comparisons or Soroban resource results.

The full outer padded-constraint fingerprint is `0d289309fc17e9b8e6e2d6a4b99d2cf4350547864fde5f79d7eb06929ee31938`, using `padded_constraints_sha256`. This covers all 131,072 constraints, including deterministic padding, and supports comparing reserve-only allocation changes in a separate port. The original unmodified native challenger gives regression vector `[394127921, 1463445479, 3541783]` for `transcript-vector.rs`; it tests two transitions from sampling to observation. The separate 32-bit port must explicitly preserve native 64-bit little-endian challenger-counter serialization because upstream uses `usize::to_le_bytes` there.
